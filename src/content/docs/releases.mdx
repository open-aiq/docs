Open AIQ ships four components that are versioned on their own: the backend
API, the web dashboard (Frontend), the device firmware (Device), and the mobile
app. A **version family** records which of their versions work together.

Each cell lists a component's exact versions in that family, with their
release dates. Expand a version for its summary, release notes, and downloads. A dash means the component wasn't
part of that family.

## Versions

Before 1.0, every minor version can break compatibility, so each `0.x` family
has its own table. From 1.0 on, there is one table per major version.

## How releases are registered

The registry lives in
[`src/data/versions.json`](https://github.com/open-aiq/docs/blob/main/src/data/versions.json)
and is published at [`/versions.json`](https://docs.air-iq.net/versions.json).
Every component's `make release` checks it before building or tagging:

- A **patch** release (`0.4.1`, `0.4.2`) is allowed when its `major.minor` is
  already registered for that component.
- A new **major or minor** version must be registered first: add it to a new
  or existing family, merge the change, and wait for this site to deploy.
  Until then, the release is refused.
- If the registry can't be reached, the release is refused too, so versions
  never drift from what's documented here.

New GitHub releases appear in the tables automatically when the site is next
deployed. To give one a short label, add it to the family's `releases` list,
for example `{ "version": "0.4.1", "info": "API fix" }`.
