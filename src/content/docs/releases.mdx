The backend, dashboard (Frontend), firmware (Device) and mobile app are
versioned separately. A **version family** records which versions work together.

Each cell lists a component's versions and release dates; expand one for notes
and downloads. A dash means the component isn't in that family.

## Versions

Before 1.0, any minor version can break compatibility, so each `0.x` family
has its own table. From 1.0, there's one per major version.

## How releases are registered

The registry lives in
[`src/data/versions.json`](https://github.com/open-aiq/docs/blob/main/src/data/versions.json)
and is published at [`/versions.json`](https://docs.air-iq.net/versions.json).
Every component's `make release` checks it before building or tagging:

- A **patch** release (`0.4.1`, `0.4.2`) is allowed when its `major.minor` is
  already registered for that component.
- A new **major or minor** version must be registered first: add it to a new
  or existing family, merge, and wait for this site to deploy. Until then, the
  release is refused.
- If the registry can't be reached, the release is refused.

New GitHub releases appear in the tables on the next deploy. To label one, add
it to the family's `releases` list, for example
`{ "version": "0.4.1", "info": "API fix" }`.
