Errors use [RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html)
(`application/problem+json`). Branch on `type`, `status` and structured
extensions; `detail` is for people, not parsing.

```json
{
  "type": "https://docs.air-iq.net/reference/errors/#validation-error",
  "title": "Request validation failed",
  "status": 422,
  "detail": "One or more request values are invalid.",
  "instance": "/api/v1/devices",
  "errors": [
    {
      "in": "body",
      "name": "name",
      "code": "required",
      "detail": "name is required"
    }
  ]
}
```

## Problem fields

| Field      | Meaning                                                                       |
| ---------- | ----------------------------------------------------------------------------- |
| `type`     | Stable identifier; links to its problem type below.                           |
| `title`    | Short title, the same for every occurrence of that type.                      |
| `status`   | HTTP status, repeated in the body for stored responses and tooling.           |
| `detail`   | Safe, human-readable guidance for this occurrence.                            |
| `instance` | Request path for this occurrence, without query string or credentials.        |
| `errors`   | Optional list of invalid inputs.                                              |

Each `errors` item has an `in` location (`body`, `query` or `path`), an input
`name`, a stable `code` and a human-readable `detail`. One response can list
several fields.

Input problems map to these statuses:

| Problem | Status |
| --- | --- |
| Malformed JSON | `400` |
| Oversized content | `413` |
| Unsupported media type | `415` |
| Well-formed input that violates the endpoint contract | `422` |
